# Third-party material

Rust dependency versions/checksums are recorded in Cargo.lock. Their licenses
remain their own; `cargo-deny` checks the resolved graph. They are downloaded
from the public registry, not copied or re-licensed as project source. Python
cryptography and system libsodium/libargon2 are independent test tools.

## IETF vectors

`test-vectors/hpke-rfc9180.json` is an unmodified selected JSON vector object
from the CFRG HPKE repository, mode=0/kem=32/kdf=1/aead=3. Its source is pinned at
[b1f7cb0cdeab6906c61b3d6574e8bdfdbe1cd3fb](https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/b1f7cb0cdeab6906c61b3d6574e8bdfdbe1cd3fb/test-vectors.json).
`hpke-official.csv` is the derived first-seal vector in a tabular representation.
The repository's [license](https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/b1f7cb0cdeab6906c61b3d6574e8bdfdbe1cd3fb/LICENSE.md)
refers to its [contribution terms](https://github.com/cfrg/draft-irtf-cfrg-hpke/blob/b1f7cb0cdeab6906c61b3d6574e8bdfdbe1cd3fb/CONTRIBUTING.md)
and IETF Trust provisions for code components. Attribution: IETF Trust and the
persons identified as the HPKE document/vector authors, including Richard
Barnes, Karthikeyan Bhargavan, Benjamin Lipp and Christopher A. Wood.

Tests also use the public known-answer vectors from
[RFC5869](https://www.rfc-editor.org/rfc/rfc5869),
[RFC9106 §5.3](https://www.rfc-editor.org/rfc/rfc9106#section-5.3) and the
[XChaCha draft](https://www.ietf.org/archive/id/draft-irtf-cfrg-xchacha-03.html).
The test/oracle implementations are project code; those embedded vector bytes
retain their IETF attribution and rights. RFC5869 authors: Hugo Krawczyk and
Pasi Eronen; RFC9106: Alex Biryukov, Daniel Dinu, Dmitry Khovratovich and Simon
Josefsson; the cited XChaCha draft: Scott Arciszewski.

IETF code components use the Revised BSD terms in
[IETF Trust TLP §4](https://trustee.ietf.org/documents/trust-legal-provisions/tlp-5/),
not a new NC Software Engineering copyright claim. See the retained
[BSD license](LICENSES/BSD-3-Clause.txt) and fixture sidecars. Their public test
keys are intentionally reproducible and must never be used for real data.
Other project vectors are deterministic synthetic encodings generated by the
independent project oracles. `test-vectors/sha256.json` freezes all input bytes.
